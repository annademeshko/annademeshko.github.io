Как я собрала дашборд безопасности, где каждая из трёх ролей за минуту собирает свою аналитикуTrack: security dashboard

Track состоит из виджетов: DevOps, аналитик безопасности и менеджер собирают на нём аналитику, которая нужна каждому.A widget-based security dashboard: each role assembles its own overview and drills into details without losing the big picture.

Контекст

У команд безопасности были разные первые вопросы:Security teams started from different first questions:

  • DevOps следил за репозиториями;DevOps watched the repositories,
  • аналитик безопасности следил за критичностью уязвимостей и приложениями;the AppSec analyst — severity and applications
  • менеджер следил за политиками и нарушениями.the manager — policies and violations

Один статичный дашборд одним ролям давал лишний шум, а другим оставлял слепые зоны.A single static dashboard couldn't serve everyone: it gave noise to some roles and blind spots to others, and each team still pulled the metrics it needed by hand or went to a neighbouring team for them.

Задача

Дать каждому контроль над своей аналитикой и не превратить настройку в конфигуратор.I had to give users control over their overview without turning setup into a complex configurator. The empty state had to lead to the first action, and the widget picker had to explain the choice before applying it.

Исследование

Запросы приносили аналитики, а решения мы проверяли на внутренних пользователях:

  • Кликабельные прототипы: смотрели, как роли собирают свою аналитику с пустого экрана.
  • A/B-тесты: сравнивали варианты перед выбором финального.

Вывод: у каждой роли свой первый вопрос.

Ключевые решенияKey decisions

Ролевые вопросы, а не типы графиков.How to organize the dashboard: by chart types or by role questions. У DevOps, аналитика и менеджера разный первый вопрос, а витрина графиков «на все случаи» давала шум.I chose to build the overview around role questions (severity, repositories, policies), because DevOps, the analyst and the manager each start from a different first question. I rejected an all-purpose gallery of charts: it gave noise to some roles and blind spots to others.

Лёгкий выбор виджетов, а не конфигуратор.Setup: a full configurator or an empty state with a widget picker. Свою аналитику можно собрать примерно за минуту, а конфигуратор отпугивал бы ещё до старта.I chose a light picker with previews and Select all — the path from an empty screen to the first overview takes a minute. I rejected a complex configurator: it turns the start into a separate job and scares off some roles before their first overview.

Раскрытие на месте, а не отдельная страница.Detail: a separate page or an expanded view in place. Так пользователь не теряет общую картину.I chose to expand a widget into a detailed mode right inside the dashboard, with a one-click return. I rejected moving to a separate details page: the user lost the context of the overview and a sense of where they were.

РешениеSolution

Пустой дашборд как точка старта:The empty state as a starting point, not a dead end: сразу предлагает добавить виджет.the empty screen immediately offers an action — add a widget. A large “+” area shows that a personal overview will appear here.

Выбор виджетов с превью:Widget picker: an informed choice: видно, что получится, ещё до подтверждения.the picker shows widget previews before confirmation. Select all speeds up the start, manual selection gives control, and active badges show the current set.

Заполненный дашборд:Populated dashboard: a single security overview: критичность, приложения, репозитории и политики в одном месте.the overview brings together severity, vulnerable applications, blocked repositories and policy triggers. The Critical/High/Medium/Low/Informational color system stays consistent across all widgets.

Раскрытый виджет:Expanded view: detail without losing context: подробный график без потери контекста и возврат к дашборду в один клик.a widget expands into a detailed mode with a stacked bar chart, time period and severity hover states. You can return to the overview in one click.

РезультатOutcome

  • ≈ 1 минута, чтобы собрать свою аналитику под роль≈ 1 minute to assemble a personal overview for your role без конфигуратора.— the empty state and widget picker lead from a blank screen to the first overview without a configurator.
  • 3 роли в одном дашборде:3 roles — one dashboard: каждый собирает свои метрики в одном месте.DevOps, the analyst and the manager assemble the metrics they need in one place and stop arguing over whose dashboard is the “right” one.
  • 5 уровней критичности в единой системе:5 severity levels in one system: одни цвета во всех виджетах, и новый виджет не ломает остальные.Critical / High / Medium / Low / Informational keep colour consistent across every widget, and a new widget is added without breaking the rest.

Чему я научилась

Дашборд для нескольких ролей должен отвечать на первый вопрос каждой роли, а не быть набором графиков. И лёгкий старт важнее гибкой настройки.
